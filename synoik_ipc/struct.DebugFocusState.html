Expand description

The live overview, keyboard-focus and input-method state — a debugging snapshot.

Every field here is one that a 2026-08-15 wedge had to be inferred from side effects: the overview’s open flag disagreeing with its progress, keyboard focus being on neither a window nor the overview, and the input method’s focus flapping. Read together they say which of those is true in one command.

Fields§

§overview_open: bool

Layout::is_overview_open() — the flag, which is what the IPC and the panel consult.

§overview_progress: Option<f64>

The overview’s animation progress, 0 closed to 1 open. None while overview_open is true is the desync: it makes render_above_top_layer() true again, so a fullscreen window draws over the overview.

§overview_progress_kind: Option<String>

Which kind of progress it is: Open, Animation or Gesture.

§render_above_top_layer: Option<bool>

Whether the focused monitor is drawing a window above the top layer — the predicate that hides the overview and the panel behind a fullscreen window.

§keyboard_focus: String

The compositor’s keyboard focus, as its variant name. Layout with no surface means nothing is focused and the overview does not hold focus either.

§input_method: bool

Whether an input method is configured at all.

§im_focus: String

Which entry the engine is focused on: None, Client, or Shell(<entry>).

§im_connected: bool

Whether the worker has a live ibus connection.

§im_client_enabled: bool

Whether the focused client has text input enabled — one input to im_focus, and the thing that flapping makes the engine’s focus flap.

§im_pending_keys: usize

How many keystrokes are held back awaiting a verdict.

§im_unanswered: u32

Consecutive keys that expired unanswered.

§im_unresponsive: bool

Whether that tripped passthrough — keys stop being held for a verdict.

§outputs: Vec<DebugOutputState>

Per-output redraw state — the other way a screen freezes while the compositor is alive.

§peek_up: bool

Whether the workspace peek’s strip is down over the live desktop.

§overlay_key_held: bool

Whether the overlay key is being held — the peek’s hold, and what a Shift press toggles against. A hold with no peek is the state a long Super press leaves behind.

§peek_trigger_held: bool

Whether the peek’s trigger key is down. It gates the toggle on the key’s edge, so a trigger stuck down would make further presses do nothing.

§strip_progress: Option<f64>

How far the thumbnail strip has come down, 0 to 1. None is a strip that is not drawing — including a peek that is up but refusing to draw over a fullscreen window.

§strip_thumbs: Vec<(f64, f64, f64, f64)>

Each thumbnail’s rect in the strip, in logical coordinates — what a capture has to be measured against to say whether a thumbnail drew what it should have.
