# D-Bus surface audit — what a GNOME session expects, and what we answer

The member tables here are generated by `tools/dbus-diff/dbus-diff.py`, which diffs every
`#[interface(name = …)]` block under `src/` against the reference XML in
`~/Projects/{mutter,gnome-shell}/data/dbus-interfaces/`. Re-run it rather than trusting a table
that has aged.

**A name diff counts stubs as served.** `DisplayConfig::night_light_supported`
(`src/dbus/mutter_display_config.rs:341`) returns a hardcoded `false` and reads as present; so do
`power_save_mode` (`-1`) and `set_power_save_mode` (`Unsupported`). A full row means the name
resolves, never that the behaviour is there.

**Absence is not always breakage.** Several GNOME components ship their own fallback when the shell
does not own a name, and a row that says so is worth more than a row that lists members. Each entry
below carries what a real session actually loses.

---

## 1. Interfaces we serve, with member gaps

| interface | have | missing | consequence |
| --- | --- | --- | --- |
| `org.gnome.Shell` | 7/17 | `ShowMonitorLabels`, `HideMonitorLabels`, `ShowApplications`, `FocusApp`, `FocusSearch`, `ScreenTransition`, props `ShellVersion`, `Mode`, `OverviewActive` | g-c-c's Displays panel draws no "1"/"2" overlays while you arrange monitors; nothing can identify the shell by version, or open the app grid / focus an app from outside. `Eval` is deliberately absent (§4) |
| `org.gnome.Mutter.DisplayConfig` | 7/16 | `SetCrtcGamma`, `GetCrtcGamma`, `SetOutputCTM`, `Backlight`, `SetBacklight`, `ChangeBacklight`, prop `Backlight`, `HasExternalMonitor`, legacy `GetResources`/`ApplyConfiguration` | colour profiles and calibration have no entry point. The backlight trio is the newer panel API; we serve `org.gnome.Shell.Brightness` and own the hardware directly (`src/backlight.rs`), so this is a compatibility gap, not a functional one |
| `org.gnome.Mutter.ScreenCast.Session` | 6/7 | `RecordVirtual` | the portal cannot open a virtual (headless) recording stream |
| `org.gnome.Mutter.ServiceChannel` | 1/2 | `OpenWaylandConnection` | low consequence — xdg-desktop-portal-gnome calls `OpenWaylandServiceConnection`, which we do serve |
| `org.gnome.Shell.Screencast` | 4/5 | signal `Error` | a recording that fails mid-flight tells its client nothing |

Full parity: `org.gnome.ScreenSaver`, `Shell.Screenshot`, `Shell.Introspect`, `Shell.Brightness`,
`Mutter.ScreenCast`(+`.Stream`), `Mutter.IdleMonitor`, `SessionManager.EndSessionDialog`,
`freedesktop.Notifications`, `gtk.Notifications`, `freedesktop.a11y.KeyboardMonitor`.

`org.freedesktop.ScreenSaver` (the inhibit half) and `org.kde.StatusNotifierWatcher` have no GNOME
reference XML; both are ours to define.

## 2. Names we do not serve

**Nothing else covers these:**

| name | members | what is lost |
| --- | --- | --- |
| `org.gnome.Mutter.RemoteDesktop` (+`.Session`) | 3 + 29 | screen sharing *with input*. The portal binds it, so remote-control sessions cannot start at all |
| `org.gnome.Mutter.ColorManager` (+`.Calibration`) | 1 + 4 | monitor calibration; the sibling of the gamma trio above |
| `org.gnome.Mutter.InputCapture` (+`.Session`) | 2 + 13 | the InputCapture portal — pointer/keyboard capture for input-leader setups |
| `org.gnome.Shell.AudioDeviceSelection` | 3 | the "what did you just plug in?" chooser; `gsd-media-keys` binds it |
| `org.gnome.Shell.PortalHelper` | 4 | captive-portal login |
| `org.gnome.Shell.ScreenTime` | 2 | wellbeing screen-time and break reminders |
| `org.gnome.Shell.Extensions` | 15 | no extension host (STRATEGY §4). Settings and the Extensions app report the shell as broken rather than as extensionless |
| `org.gnome.Mutter.InputMapping`, `org.gnome.Shell.Wacom.PadOsd` | 1 + 1 | drawing-tablet mapping and the pad OSD — consistent with the tablet deferral |

**Covered by a fallback, so the session still works:**

- `org.freedesktop.impl.portal.Access` — the portal permission dialog. xdg-desktop-portal-gnome
  ships its own `Access` implementation (`/usr/share/xdg-desktop-portal/portals/gnome.portal`), so
  the prompt appears; it is a GTK window rather than shell chrome.

**Correctly absent** — separate binaries in GNOME that we consume rather than serve:
`org.gnome.Shell.CalendarServer`, `org.gnome.Shell.HotplugSniffer`.

## 3. The other direction — interfaces we should *call* and do not

Easy to miss, because a diff of what we export cannot see them.

| name | who owns it | what we lose by not calling it |
| --- | --- | --- |
| `org.gnome.SettingsDaemon.Color` | gsd-color | **Night Light does nothing.** gsd-color owns the schedule and computes `Temperature`; mutter proxies that property (`meta-color-manager.c:310-369`) and applies a blackbody gamma LUT per CRTC (`meta-color-profile.c:405-503`). Our QS tile writes `night-light-enabled` (`src/gnome.rs:1959`) and no one consumes the result. The CRTC plumbing is already there (`src/backend/tty.rs:2148`). Two further defects ride along: `NightLightSupported` is hardcoded `false`, so g-c-c hides its Night Light panel (mutter derives it from `gamma_lut_size > 0`, `meta-monitor-manager.c:1193`); and our panel icon is gated on the gsettings key (`src/ui/panel.rs:465`) where GNOME gates on `NightLightActive` (`status/nightLight.js:70`), so the icon shows at noon under an automatic schedule |
| `org.gnome.Shell.SearchProvider2` | every app shipping a `*.search-provider.ini` | overview search is **app-only** (`src/ui/overview_search.rs`). No Files, Settings, Characters, Calculator, Contacts or Software results — and no `SystemActions` rows either |
| `org.freedesktop.NetworkManager.AgentManager` / `.SecretAgent` | NetworkManager | **served** (`src/dbus/network_agent.rs`): we register as `org.gnome.Shell.NetworkAgent` and answer `GetSecrets` from the keyring, falling back to a modal dialog. VPN is the one gap — its secrets belong to the plugin's own auth binary, so we answer `NoSecrets` and NM fails the connection promptly |
| `org.gnome.keyring.SystemPrompter` | gnome-shell in GNOME; `gcr-prompter` otherwise | keyring and SSH-key unlock prompts still appear — the name is D-Bus-activatable and falls through to `/usr/libexec/gcr-prompter`. We get a GTK window instead of shell chrome |
| `org.gnome.Shell.ClocksIntegration`, `org.gnome.Shell.WeatherIntegration` | GNOME Clocks / Weather | the date menu has no weather section. World clocks reads gsettings directly (`src/world_clocks.rs`), which is the right call for that half |

## 4. Deliberately not implemented

- `org.gnome.Shell.Eval` — gated behind unsafe-mode upstream and a remote-code hole. It is
  unimplemented on purpose; do not read the empty row as forgotten.
- `org.gnome.Mutter.X11`, `org.gnome.Mutter.Devkit`, `org.gnome.Mutter.DebugControl`,
  `org.gnome.Shell.PerfHelper` — upstream-internal or debug-only.

## 5. Expired premises

A recurring bug class, not a list: a simplification that was true when written, whose premise later
changed, and whose comment kept asserting it. The comment is the artefact that rots, and it rots
silently — every instance found so far passed its tests.

Currently open, and re-checked rather than assumed:

- no action muxer, so `open_new_window` via an app's exported `app.new-window` action, and
  `shell_app_request_quit`'s `app.quit`, both take GNOME's fallback branch;
- `can_open_new_window` cannot reach its GtkApplication rung without
  `gtk_shell1.set_dbus_properties` — which is why System Monitor offers a "New Window" it does not
  have;
- window-backed `ShellApp`s are synthesized (`window:<n>`, as GNOME does), but carry no icon of
  their own — the dash draws the `application-x-executable` fallback;
- parental controls (`malcontent`) are not modelled, so that half of the app-grid filter is inert.

The cheap recurring check: grep the tree for simplification notes ("for now", "we have no",
"not modelled", slice references) and re-test each premise rather than the code.
